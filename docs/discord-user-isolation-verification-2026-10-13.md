# Discord 逐用户隔离实现与自动验证 — 2026-10-13

这是基于 onboarding PR #5 的独立 stacked 变更。已实现可选的 Rein Discord 接入与本地受控
记忆服务；不修改上游子模块，不修改 Foundation 后端，不自动切换此前运行的本地测试实例。
按负责人本轮补充要求，先完成代码，**两个真实账号验收暂缓，不能记为通过**。

## 实现结果

- 可信原生发送者参与 session key；同频道 A/B 分开，尚未 link 的用户也先隔离。
- 公聊与私聊的 session 和持久记忆均分开；同一个人的私聊资料也不能自动进入公共回复。
- 记忆工具不接受用户 ID 或受众参数，宿主绑定当前发送者、会话与受众，并检查调用仍有效。
- 公开课程目录仍可共享。群聊缓存、引用正文、thread starter、附件与父会话不自动注入。
- 原共享频道历史不迁移到新 session；`/reset` 换干净会话并保留本范围的个人记忆，`/forget`
  删除本范围记忆并换干净会话，不影响他人。已发送的 Discord 消息和宿主历史记录不会因此删除。
- 独立公开工作区、受限工具清单和关闭原生跨会话回忆是启用前置条件，配置不满足则拒绝启动。

## 自动验证证据

配置、owner scope、记忆读写、撤销、并发、重启、重置、删除和路径边界均有针对性测试。
仓库完整测试 637 项通过，其中新增逐用户隔离测试 23 项；结构与差异格式检查通过。
最后的记忆工具元数据调整后，相关 30 项测试通过；插件入口通过当前固定 SDK 的 TypeScript 类型检查。
原生集成探针通过实际 OpenClaw 插件加载与宿主 ingress/session/model 链路，向 localhost
确定性测试模型发送 14 次请求，并真实执行记忆工具。它使用两个**模拟原生发送者**，没有
登录第二个真实 Discord 账号，也没有向 Foundation 后端伪造身份或发送业务调用。

| 检查 | 实际结果 |
| --- | --- |
| A/B 同频道交替发消息 | key 不同；B 的模型输入没有 A 的上下文或记忆标记 |
| A 公聊连续发消息 | key 相同；模型输入保留 A 自己的公开上下文 |
| A 私聊保存另一条记忆 | A 与 B 的公共模型请求都没有私聊上下文或私聊记忆标记 |
| A 重置会话 | 新 key；旧对话不再输入模型，A 自己显式保存的公开记忆仍可读取 |
| A 删除记忆 | 后续模型输入不再包含已删除记忆，B 的范围不受影响 |
| 冒充身份、跨范围工具、过期调用 | 拒绝或无法取得工具；不按模型参数选择他人身份 |

验证针对的是实际送入模型的内容及工具输出，不以“模型说自己不知道”作为隔离证据。
测试模型是确定性协议桩，因此不评价 Nori 的真实模型语气或 Discord 网络行为。

# Discord 隔离方案撤回与重新设计

[English](discord-isolation-redesign.md)

决策日期：2026-11-04（America/Los_Angeles）。对应 R01、R03、R25、US01、US02；后台身份边界继续遵循 D13。
本文区分已完成的生产回滚、本次 PR 提议的源码撤回，以及尚未实现的新方案。

## 生产处置

负责人审阅兼容性和记忆体验后，否决了替换原生 channel 的实现方式。生产 Discord 已恢复迁移前的
配置与启动器。已逐一比较恢复文件与受保护原件，确认 HTTP 就绪检查、运行中原生 `Discord` adapter
的连接状态，以及原 workspace 和频道级 @ 设置。Ask Nori 恢复免 @，私信保持原来关闭状态；模型、
后台连接、工具与记忆设置恢复原值。PR #36 的管理员归责及真实转交规则仍在部署中。

原生历史、隔离期间的新会话和 SQLite 笔记全部保留。恢复前在 Discord 停止时备份了运行状态、隔离笔记
和公共 workspace，没有合并、重新分配或删除记录。受保护备份、回执及凭据定位信息不进入 Git。
此次验证没有代成员发送真实消息。**原生群聊仍按频道共享 session；回滚恢复兼容性，没有解决用户隔离。**

| 范围 | 处理及原因 |
| --- | --- |

| PR #7 的共享核心与 Slack adapter | 不整批 revert：Slack 依赖共享核心，并有独立的传输／后台验证。本次不修改生产 Slack 配置；其替换 adapter 的设计也须在任何新上线前复核兼容性。 |
| Router 测试及模型选择 | 保留其模拟入站依赖，避免移除无关的路由覆盖；这些测试不能证明原生 Discord 的兼容性。 |

历史 PR 整批撤销会同时移除共享核心的使用方及有价值的回归测试，因此本次按依赖撤下生产连接路径。
隐私审计会拒绝所有请求启用 `rein-discord` 的配置，即使满足旧版 guard。恢复原生配置必须显式完成；
仅关闭替代插件而继续禁用原生插件，不会恢复 Discord 连接。

## 旧方案为什么不符合目标

它保留了 `discord` 标识，却没有完整保留原生 outbound/actions、媒体、交互命令和插件接口。
全局 @ 开关、专用公共 workspace、关闭原生记忆检索／自动写回，以及按用户和频道存储的显式命名笔记，
都造成了产品行为变化。这些限制不是用户隔离的必然要求。

## 新方案必须满足的行为

1. **原生 channel 兼容。** 保留原生 Discord 接入、账号与频道设置、回复／附件／线程、消息操作及
   既有插件接口。Ask Nori 免 @ 与隔离独立配置。私信将来可以按独立访问规则启用，本文不启用私信。
2. **读取历史前确定可信所有者。** 根据已认证的平台发送者、Bot、服务器和会话确定归属，在读取、
   保存、排队和摘要前落实。频道缓存、引用、线程开头、重置和并发执行使用同一边界。不能把公开频道
   伪装成私信。允许按需求使用带来源的公开引用，不能把它变成提问者的身份或个人记忆。
3. **保留有效的个人记忆。** 保留当前会话连续性、压缩、自动记忆及长期检索；在查询／存储层强制
   所有者及受众范围，不能检索混合数据后再让模型自行筛选。只有证明访问契约可靠后才复用原生索引。
   SQLite 是可选存储方式，不应把产品限制为五十条命名笔记。
4. **会话范围与记忆范围分开。** 同一用户被允许复用的偏好可以跨会话使用，由可见范围及用途决定。
   私聊内容不能进入他人上下文，也不能因同一人在公开频道提问就自动公开。跨平台绑定不自动合并
   记忆或权限；选择性共享个人信息的具体规则仍需定义。
5. **自动记忆携带来源。** 宿主写入所有者、来源消息／事件、会话、受众、时间及保留策略。区分个人
   偏好、带归属的用户陈述、派生摘要和已核实组织事实；摘要必须保留来源。重复陈述、置信度和 Nori
   自己的旧回答不能把自述升级成事实。权限始终依赖后台当前记录，支持纠正、冲突、过期和索引／缓存删除。
6. **明确工具及资源策略。** 保留有用的原生消息操作，并验证操作类型、目的地和调用者权限。公共文件
   可以使用受审阅的只读目录；已授权后台目录和网页资源不必复制进 workspace。改变目录前核对既有
   技能引用和资源清单。通用文件工具不能越过私人记忆边界，共享 USER/MEMORY 文件不等于逐用户存储。
7. **可选插件及明确关闭行为。** 关闭时与原生基线一致。开关不得改写频道配置、移动 workspace、删除
   会话或将个人记忆混入共享库。旧混合历史保留归档；只有可靠事件归属支持时才进行经过审阅的迁移，
   不从消息正文、昵称或模型猜测中分配所有者。

## 通用 workspace skills

Nori 的技能统一放在 `workspace/skills/<name>/SKILL.md`，引用文件和脚本放在该技能目录内。
它们是可复用的 workspace 能力，不属于 Discord／Slack adapter。新增技能不得要求修改
`rein-discord`、`rein-slack` 或 `rein-isolation` 的技能名白名单、复制到频道专用 workspace，
或改变会话路由。保留原生技能发现及正常的依赖／启用检查。技能可加载不代表授予工具、凭据或
后台权限；调用仍按当前用户及受众校验。个人输入、输出和记忆不属于共享技能资源。

现有 `rein-community-discovery`、`nori-browser` 和 `agent-browser` 已位于该目录。
PR #38 当前版本的求职技能也使用此目录，不修改 adapter。本 PR 恢复普通原生 Discord workspace
加载，但保留的旧 Slack guard 和历史 Discord fixture guard 仍仅接受 `rein-community-discovery`。
这是旧实现的兼容性限制，不是新增通用技能应遵循的政策。尚不能声称所有 Slack 技能兼容；
在私人文件和工具执行边界替代方案完成前，不直接放宽旧文件检查。

新隔离方案上线前，必须验证所有 workspace 技能及一个新技能（含引用文件／脚本）在隔离开关前后
均经原生机制发现，且不修改 adapter。获授权的实际使用需另行验证，同时证明私人状态不可访问。
`node scripts/verify-workspace-skills.mjs` 只验证普通 workspace 的原生发现基线，不启动频道，
不证明用户隔离或工具执行。

## 扩展点可行性验证：尚未通过

固定版本的[原生 Discord 路由](../vendor/openclaw/extensions/discord/src/monitor/route-resolution.ts)
通过 `resolveAgentRoute` 解析会话 peer，群聊路由不把发送者用作 session peer；`dmScope` 不能修复它。
[`inbound_claim` 返回值](../vendor/openclaw/src/plugins/hook-types.ts)提供 `handled` 和可选回复，
不提供逐发送者的路由覆盖。通过此 hook 接管 dispatch 也不自动保留历史处理和 outbound 语义，
更晚的提示词／工具 hook 无法证明之前的历史读取已被隔离。

原生[记忆能力注册](../vendor/openclaw/extensions/memory-core/index.ts)提供工具、回忆整合及写回计划接口；
[跨会话回忆策略](../vendor/openclaw/packages/memory-host-sdk/src/host/config-utils.ts)仍基于 agent／私聊形态，
不是通用的逐发送者 ACL。存在接口不代表新插件能透明覆盖每次索引、自动写入、召回和文件访问。

实现前必须提供本地链路证据：原生 transport 保持启用，可信所有者能在所有上述路径的正确时点建立并执行。
如果公开 SDK 缺少足够早的扩展点，先提出小范围上游接口并审阅兼容性。不得 monkey-patch 内部实现、
修改只读 vendor 源码、再次替换原生 channel，或仅凭 hook 名称就宣称完整方案可行。

## 再次上线前的验收

| 验收项 | 必需证据 |
| --- | --- |
| 原生兼容及关闭行为 | 对比插件开启／关闭与原生基线：频道 @、Ask Nori、回复引用、附件、线程、获准消息操作、身份／目录、Router 及实际已装插件 hook；开关不改变配置或 workspace。 |
| 同频道双用户及并发 | A/B 交替和并发发言，检查真实 session key、模型输入、摘要、检索及写入。A 的标记不进入 B；伪造名字、职责或 ID 无法选择其他所有者。 |
| 公私聊与允许的连续性 | A 的获准个人偏好经历重启、重置和允许的跨会话使用后仍可检索；私聊标记不进入 B 或 A 的公开回复。将来开启私信需要独立实机验收。 |
| 自动记忆与错误陈述 | 不要求每次明确说“记住”才保存。错误管理员／维护者陈述经过召回和压缩仍是未核实自述，不能改变权限或推荐负责人。 |
| 资源与工具 | 所有支持的技能／资源经受控目录或授权工具仍可访问；拒绝未授权目录、目的地修改及跨用户读写。 |
| 生命周期与回滚 | 索引、摘要、纠正、删除和活动调用都执行所有权规则，覆盖并发 forget/reset；开关与回滚保留两套存储且不静默导入混合历史。 |
| 实机验收 | 在已有测试频道使用两个获授权真实账号，检查模型输入和工具证据，也检查可见回复；合成探针和 connected 状态不能代替此项。 |

当前 PR 撤下旧生产接入并记录上述要求，不实现替代方案，也不声称可行性验证或实机验收已通过。

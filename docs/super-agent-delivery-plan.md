## 范围与已有成果

Super Agent 负责理解目标、选择能力、按需委派、检查成果、持续推进、改向/取消/恢复与授权交付。
通用工具优先使用 OpenClaw 原生能力及社区集成；只有复现具体集成缺口才增加必要薄适配。
不建设替代工具平台、调度器、记忆引擎或通用业务工作流平台。

保留已有任务委派、任务续接核心、ACP 编码接入、身份与工具权限、路由、日报，以及
合作邮件审批与测试发送集成。保留 Community 信息、用户社媒账号与 Community 邮箱关联等
Rein 内部能力及其 backend 权限；此次不扩大其业务功能。保留能力不等于宣称全部产品验收通过。
邮件是可选业务集成，其真实发送验收单独保留，不阻塞 Super Agent 完成。

以下任务不要求新增真实内部业务功能。任何新缺口必须先区分原生能力配置、已有社区集成、
Rein 特有 API、实际 SDK 缺口，再决定是否需要开发。缺少工具时准确报告，不能伪造执行或成果。

## 推进顺序与完成判定

1. 先核对已有实现与验收证据，避免重做已完成开发；保留运行限制诊断，但按负责人已确认的范围将更严格的整链保证移至后续增强，不重新阻塞当前任务。
2. 补齐任务执行/续接实际缺口，确定摘要保留与回传标准，同时验证所需身份、记忆和 Provider 边界。
3. 使用已有工具完成跨业务复用与隔离仓库开发闭环。相关检查通过后才登记通用 Super Agent 验收；
   未解决的核心验收项继续阻塞完整完成，不能用“功能已合并”替代。
4. 社区上线/共享 Gateway 迁移及运维报表单独验收，不把它们混作通用任务能力，亦不降低原上线要求。
5. Super Agent 完成后，再由 Nori 主导内部业务工具扩展。每次交付区分本地实现、测试、审阅、合并、
   部署和真实业务验收；授权覆盖到哪一步，就执行到哪一步并明确剩余交接。

各项验收记录任务内容、版本/环境、负责人、输入与预期、实际输出、检查结果、失败/跳过项及下一步。
合成测试、真实原生集成、真实用户/Provider 验收分开标注；现有邮件检查仍只证明其记录范围。
本次没有修改既有工具行为、关闭 Issue、勾选产品验收或授权任何线上操作。

## Super Agent 完成后的业务扩展

由 Nori 调查 Rein 内部系统与现有接口的实际缺口，提出有证据的优先级，经适用的产品决策后执行。
候选包括 Community 业务操作、社媒/邮箱关联增强以及其他内部组织流程；这些是待调查方向，
不是此次新增承诺。优先复用 OpenClaw/社区工具，Rein 自有工具只承担内部系统特有能力。

Nori 应主导从需求、方案、实现到验收的全过程；不能因拥有工具或加载 Skill 就取得新的业务权限。
不自动创建生产账号、发邮件、发布、合并或部署。测试中的能力缺口不自动转化为生产扩展任务。
